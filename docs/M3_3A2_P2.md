## 4. Batch limits and timing semantics

- `HWIO_MAX_RECORDS = 256` per call
- `HWIO_MAX_PULSES_RECORD = 16 384`
- `HWIO_MAX_TOTAL_PULSES = 262 144` per call
- Validation is atomic: the batch is either fully applied or fully rejected.
- Ordering is stable-sorted by `(suborder, original_index)`.
- Every pulse invokes `UnprogrammedIncrement` once; opposing pulses are
  **not** algebraically collapsed.
- CDU counters route through `PushCduFifo` inside `UnprogrammedIncrement`,
  preserving one-pulse-per-cycle FIFO servicing.

`UnprogrammedIncrement` executes non-CDU counter arithmetic immediately
on invocation and enqueues CDU pulses on the per-axis FIFO (drained one
pulse per `agc_engine` tick by `CduChecker`). This is the same path
the emulator uses for its native socket-packet UP-sequences. It is not
sub-instruction cycle-accurate pulse timing and is not described as such.

## 5. Output-trace layout and overflow

```c
struct AgcOutputTraceEntry {   // sizeof == 32, verified via _Static_assert
  uint32_t sequence_hi, sequence_lo;   // 64-bit monotonic sequence
  uint32_t cycle_hi,    cycle_lo;      // 64-bit agc_engine tick counter
  uint16_t address;
  uint16_t operation;                  // 0 = WRITE (AGC store)
  int32_t  delta;                      // valueAfter - valueBefore
  uint16_t value_before, value_after;
  uint16_t _pad;
};
```

- Ring capacity: 4 096 entries.
- Overflow: `TraceDropped` increments; oldest entry is overwritten.
- Sampling point: after each `agc_engine()` tick inside `cpu_step`, before
  control returns to JS. This captures every net change to a whitelisted
  observable-output counter with stable ordering.
- Drain is read-only w.r.t. AGC state.
- `cpu_reset()` clears the trace and baseline cache: a new AGC epoch
  cannot inherit stale observations.

## 6. Native-path proof

`agc_counter_increment` calls `UnprogrammedIncrement(&State, addr, inc)`
directly — the same symbol the emulator's own packet-driven UP-sequences
call. No raw erasable assignment path is exposed. Smoke test:
`agc_counter_increment(0o37, 0)` (PIPAX PINC) advances `State.Erasable[0][037]`
from 0 to 1 through `CounterPINC`, matching authentic Pinc semantics.

## 8. P2 tests

`src/sim/agc/__tests__/hwioExtWasm.test.ts` loads the extended artifact
directly (bypassing the M2/M3.1/M3.2 adapter/Worker path) and verifies:

- Extended WASM instantiates against a plain `env.memory` + WASI stub.
- All nine legacy exports are present.
- All nine approved extension exports are present. No unexpected extras.
- `version()` still returns `"2020-12-24 ddc65e7be"`.
- `agc_ext_version()` returns `"ddc65e7be+apollo-browser-hwio-v1"` and
  `agc_hwio_version()` returns `1`.
- `agc_out_trace_entry_size()` returns `32`.
- `agc_counter_increment` rejects: THRUST (0o55), TIME1 (0o25), unmapped
  (0o60), invalid IncType.
- Allowed PIPA PINC increment reaches native `UnprogrammedIncrement` and
  advances `State.Erasable[037]` correctly.
- Batch validation is atomic (a bad record leaves AGC state unchanged and
  reports the offending index via `agc_hw_input_last_error_index`).
- Batch is stable-sorted by `(suborder, original_index)`.
- Opposing pulses in one batch remain separate.
- Trace drain returns 0 entries on a workload with no whitelisted-counter
  motion, and a second drain is empty. Reset does not disturb AGC state.

## 9. P2 stop gate

- The extended artifact is **not** promoted. `AgcCoreAdapter` and
  `AgcWorker` continue to load `yaAGC.wasm`.
- All frozen M2/M3.1/M3.2 tests continue to pass because no production
  code path changed.
- P3 (frozen vs extended behavioural parity) is safe to begin: the
  extended artifact retains the full legacy export shape, preserves
  memory import semantics, keeps `version()` intact, and does not
  observably behave differently until a new export is called. That is
  precisely the condition P3 is designed to verify at scale.

Closed-loop and monitor-mode Worker integration remain prohibited.
