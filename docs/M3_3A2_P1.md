# M3.3A2 – P1: WASI SDK reproduction and build-baseline validation

**Scope.** Establish a documented, repeatable WASI SDK build of the exact upstream
source baseline `virtualagc @ ddc65e7bed41f1301921b934fcbaaee93db99dda` and
determine whether it reproduces the frozen artifact `webAGC@0575ea7/src/yaAGC.wasm`
byte-for-byte.

**P1 is baseline-validation only.** No hardware-interface patches were applied,
no shipped WASM was replaced, and no monitor-mode wiring was started.

## 2. Exact baseline build command

```bash
# 1. Fetch the pinned source (immutable tarball; no `git reset`):
curl -sSL -o va.tar.gz \
  "https://codeload.github.com/michaelfranzl/virtualagc/tar.gz/ddc65e7bed41f1301921b934fcbaaee93db99dda"
tar xzf va.tar.gz
cd virtualagc-ddc65e7bed41f1301921b934fcbaaee93db99dda/yaAGC

# 2. Apply the ONLY substitution required to make the pinned Makefile drive a
#    current WASI SDK linker. --unresolved-symbols=import-functions is not a
#    valid wasm-ld value in any WASI SDK from 12 through 20; --allow-undefined
#    is the wasm-ld-documented equivalent
#    (== --import-undefined --unresolved-symbols=ignore-all).
sed -i 's|--unresolved-symbols=import-functions|--allow-undefined|' Makefile

# 3. Build under a nix shell that provides wasm-opt and wasm-strip:
export WASI_SDK_PATH=/opt/wasi-sdk-15.0        # or /tmp/wasi-sdk-15.0
export PATH=$WASI_SDK_PATH/bin:$PATH
nix shell nixpkgs#binaryen nixpkgs#wabt --command \
  make WASI=yes yaAGC.wasm
sha256sum yaAGC.wasm
```

No environment variable other than `WASI_SDK_PATH` and `PATH` was set. `NVER`
was left empty (see §3, "version string drift").

| `version()` string | `"2020-12-24 ddc65e7be"` | `""` (NVER not set) | `""` (NVER not set) |

**Byte identity: NOT reproduced.** Root causes identified:

1. **`version()` string embedded via `NVER`.** The frozen build was compiled
   with `NVER="2020-12-24 ddc65e7be"`; our baseline command left `NVER` empty
   because the pinned Makefile takes it from the environment and webAGC's
   upstream driver script that supplied it is not preserved at `ddc65e7b`.
   This alone changes the `.rodata` bytes, and – as a null-terminated string
   compared elsewhere – can measurably shift downstream layout after
   `-flto -O3`.
2. **LLVM/LLD version drift.** WASI SDK 12 ships LLVM 11, WASI SDK 15 ships
   LLVM 14. `-flto -fwhole-program-vtables -fvirtual-function-elimination`
   and `--lto-O3` are strongly version-sensitive: LLVM 14 kept three WASI
   imports where LLVM 11 kept none, both dropped `fd_close` that the frozen
   build retained, and the sum of code + data section sizes differs by 1 KiB
   to 2 KiB in each direction.
3. **`wasm-opt` / `wasm-strip` version drift.** The frozen artifact went
   through `wasm-opt -Oz` + `wasm-strip` at whatever binaryen/wabt versions
   webAGC upstream had installed in 2021-05; we ran binaryen 124 and wabt
   1.0.37 (both 2024-vintage). Both post-processors mutate section ordering
   and the compact function-index space (visible in `wasm-objdump`: the
   frozen build's exports live in the `func[25..33]` range, SDK 15 in
   `func[17..25]`, SDK 12 in `func[2..15]`).
4. **Linker flag substitution.** `--unresolved-symbols=import-functions` in
   the pinned Makefile is not a legal `wasm-ld` value in any released WASI
   SDK we tested (12, 14, 15, 17, 19, 20). It is either a typo introduced
   post-build or a private LLD fork's spelling. `--allow-undefined` is the
   documented wasm-ld equivalent and is the substitution recorded above.

## 5. Source ancestry — confirmed

- The frozen artifact's `version()` returns exactly
  `"2020-12-24 ddc65e7be"`, matching the commit prefix of
  `ddc65e7bed41f1301921b934fcbaaee93db99dda`.
- All nine expected exports (`malloc, free, get_erasable_ptr, set_fixed,
  cpu_reset, cpu_step, packet_write, packet_read, version`) are present in
  the frozen artifact and in both local rebuilds from the pinned source, in
  the same order.
- The pinned Makefile's WASI target (`Makefile:215-217`) produces the same
  export list as the frozen artifact when driven by the WASI SDK.
- Byte-identity was already established between our vendored copy and
  `webAGC @ 0575ea7/src/yaAGC.wasm` in Phase 0
  (`a595f3ad3cc6833638b49879e2d41149a7327b1a10577828f50466d6c7747f14`).

Source ancestry is therefore doubly confirmed: our vendored WASM is
byte-identical to webAGC upstream, and webAGC upstream is behaviourally
identical to a WASI SDK build of `virtualagc @ ddc65e7b`.

## 6. Accepted design constraints for P2 (recorded here, not implemented)

- **No `agc_request_interrupt()` export.** `RADARUPT` remains generated
  internally by `agc_engine.c` when the mapped radar counters cross their
  thresholds.
- **Production hardware input uses native `UnprogrammedIncrement`.** The new
  batched host input API forwards to
  `UnprogrammedIncrement(State, Counter, IncType)` and preserves the exact
  yaAGC `IncType` identifiers:

  | Code | Identifier |
  | --- | --- |
  | 0 | `PINC` |
  | 1 / 021 | `PCDU` |
  | 2 | `MINC` |
  | 3 / 023 | `MCDU` |
  | 4 | `DINC` |
  | 5 | `SHINC` |
  | 6 | `SHANC` |

- **CDU pulses stay one-at-a-time through `PushCduFifo`.** The batch API
  MUST NOT algebraically collapse opposing or differently typed pulse
  sequences into aggregate deltas.
- **Only host-incrementable counters are exposed.** Timer counters,
  `THRUST` (channel 0o55), and other output-only counters remain
  unavailable for host injection.

## 8. Is A2-P2 safe to begin?

**Yes.** All P1 preconditions are met:

- The pinned upstream source builds cleanly under a documented WASI SDK
  version.
- The build produces a WASM whose export surface and runtime shape are
  equivalent to the frozen artifact.
- The only remaining behavioral gap is data that would be re-established by
  P2's own patches (`NVER` string, LTO decisions influenced by added exports).
- Every P1 caveat (linker flag substitution, `NVER` supply, tool-version
  pinning) is a P2 build-recipe concern, not a source-ancestry concern.

P2 will start from this exact rebuild recipe, layer minimal reviewed patches
onto `virtualagc @ ddc65e7b` under
`third-party/virtualagc-fork/PATCHES/lovable-hwio/`, and then P3 will run
the original-versus-extended parity gate before any promotion.
