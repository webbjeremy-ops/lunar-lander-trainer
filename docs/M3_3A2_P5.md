# M3.3A2-P5 — Descent monitor mode (freeze)

SPDX-License-Identifier: GPL-3.0-or-later

Status: **FROZEN**. Phases P5.a–P5.e complete. Everything below is the
authoritative description of what monitor mode does and — equally
important — what it deliberately does not do.

## 1. Scope and prohibition

`discrete-observer-v0` is a **diagnostic discrete interface**, not a
powered-descent monitor and not a control path.

* It injects only source-mapped avionics **discretes** into CHAN 030/033.
* It observes CHAN 011 (engine discretes), CHAN 014 (thrust drive activity)
  and the THRUST output counter (0o55) losslessly.
* It never writes to the LM physics kernel. Closed-loop control remains
  prohibited for the whole of M3.3.
* Landing-radar altitude/velocity and PIPA increments remain **unresolved**;
  `descent-monitor-v1` is therefore permanently blocked in this milestone
  with `unresolved-sensor-mapping` reasons drawn from the registry.
* DPS **throttle magnitude is not derived**. `throttleFraction` is `null`
  and the UI renders `PHYSICAL THROTTLE SCALE NOT YET RESOLVED`.

## 2. Simulation protocol v2

`sim:ready` now reports `simulationProtocolVersion: 2` and
`supportedMonitorProfiles`. The frozen M2 `ReadyPayload` is untouched
(`src/agc/__tests__/readyProtocolCompat.test.ts`); monitor capability is
carried by additive simulation-protocol messages only.

New commands (all epoch-checked, all applied at a tick boundary):

| Command | Effect |
| --- | --- |
| `sim:set-avionics` | Records the operator-declared discrete state. The Worker never invents avionics values. |
| `sim:set-monitor-profile` | Queued to a tick boundary; answers with `sim:commandAck` or `sim:monitor-blocked`. |
| `sim:request-monitor-trace` | Returns the retained diagnostic window plus WASM dropped/pending counts. |

## 3. Worker-owned state

All monitor state lives in `MonitorController` inside the AGC Worker; React
holds none of it and receives compact `AgcMonitorSnapshot`s.

* **Input shadow** — `AgcInputChannelShadow` is the authoritative record of
  every host-written input channel, seeded from yaAGC's own
  `agc_engine_init` values (CH030 `0o37777`, CH031/032/033 `0o77777`) and
  the frozen adapter's post-`cpu_reset` writes. `packet_write` is a
  whole-word store, so every owned-bit update is merged
  `(current & ~mask) | (value & mask)` before transmission. Unowned bits
  (DSKY keys, PROCEED) are provably preserved.
* **Snapshot** — `inputChannels` exposes CHAN 030/033 as complete octal
  words with the active profile's owned mask, so the harness renders
  authentic values rather than reconstructions.
* **Trace ring** — a bounded 2048-entry Worker ring, distinct from the WASM
  4096-entry output-counter ring. Overflow is reported, never hidden; both
  dropped counters are surfaced separately.

## 4. Atomic entry, interlocks

Entry order is mandated and unit-tested: `resetTrace` → verify drained empty
→ `setTraceEnabled(true)` → verify enabled. A blocked request performs no
partial arming.

Blocking reasons include `no-active-scenario`, `prerequisite-missing`
(no declared avionics, wrong HW-I/O version) and `unresolved-sensor-mapping`.

Interlocks disarm the trace and never re-arm implicitly:
`agc-reset`, `agc-epoch-changed`, `scenario-reset`, `terminal-state`,
`trace-unexpectedly-disabled`, `invalid-sensor-action-set`,
`worker-disposed`.

## 5. Physics firewall

`src/simulation/runtime/physicsControl.ts` brands `ResolvedPhysicsControl`
with a module-private `unique symbol`, so no value derived from AGC output
can be passed into the kernel. The guard is asserted at compile time with
`@ts-expect-error` in the P5.a tests.

## 6. Acceptance evidence

* Vitest: **326 passing** (37 files), including 20 `MonitorController`
  lifecycle cases (dormancy, atomic entry, unowned-bit preservation,
  idempotency, interlocks, bounded retention).
* Playwright, Wrangler-served production bundle
  (`tests/monitor-mode.spec.ts`, 6 specs):
  1. protocol v2 on a **single** Worker; only `/agc/yaAGC-ext.wasm` fetched;
     monitor dormant by default;
  2. entry arms the trace, renders CHAN 030/033 as complete octal words with
     a non-empty owned mask, and produces `IN CH03x` merge rows in the
     retained window;
  3. `descent-monitor-v1` blocked with authentic reasons and no partial
     entry;
  4. exit disarms the trace and clears retained diagnostics;
  5. scenario reset interlocks rather than re-arming;
  6. **LM physics is bit-identical** with the monitor on and off — two fresh
     sessions publish identical `(altitude, vertical velocity, propellant)`
     for every shared `scenarioElapsedUs` key.
* Golden touchdown unchanged: `touchdownTimeUs = 368_279_425`.
