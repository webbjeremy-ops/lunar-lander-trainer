# M3.3A2-P4 Acceptance — Canonical runtime promotion

## Decision

`yaAGC-ext.wasm` (HW-I/O v2, tag `apollo-browser-hwio-v2`, SHA-256
`aec84b4736b2a8f80709d6a8c8ccceec51f1f3955144a9fad771118c9a21262e`) is
now the sole AGC runtime the browser application instantiates. The frozen
`yaAGC.wasm` remains vendored solely as a parity reference for
`src/sim/agc/__tests__/hwioParity.test.ts`.

## Single source of truth

`src/agc/AgcRuntimeManifest.ts` exports `CANONICAL_AGC_RUNTIME`. All
production paths derive the WASM URL from it:

- `src/sim/agc/roms.ts` — `agcWasmUrl()` delegates to the descriptor.
- `src/agc/AgcSession.tsx` — session singleton uses `agcWasmUrl()`.
- `src/ui/dsky/Dsky.tsx`, `src/routes/capture.tsx` — via the session.
- `src/agc/AgcWorker.ts` — validates identity at boot; refuses to enter
  `ready` if the loaded artifact lacks HW-I/O v2 exports or is armed for
  tracing at boot.

## ABI validation

At the end of the `initialize` handler the Worker calls
`AgcCoreAdapter.extensionIdentity()` and fails with a `fatalError` (and
never reaches `ready`) when any of the following holds:

- `agc_hwio_version()` is absent, i.e. the frozen artifact was fetched
  (`agc-runtime-not-extended`).
- `agc_hwio_version()` !== 2 (`agc-hwio-version-mismatch`).
- `agc_out_trace_enabled()` or `agc_out_trace_dropped()` is nonzero at
  boot (`agc-runtime-not-dormant`).

The existing yaAGC source-commit substring check
(`EXPECTED_YAAGC_VERSION_SUBSTRING = "ddc65e7b"`) still runs first.

## Diagnostics surface

`ReadyPayload.extensionIdentity` and `Diagnostics.extensionIdentity`
carry `{ hwioVersion, extVersion, extensionTag, traceEnabled,
traceDropped }`. `DiagnosticsPanel` renders each field so the running
identity is human-inspectable on `/sim`, `/learn`, `/explore` and
`/capture`.

## Dormancy contract (production default)

The extended runtime never has trace collection armed by production
code. There is no code path in `src/` that calls
`agc_out_trace_set_enabled(1)`; the descriptor's dormancy invariant is
enforced at boot and re-checked whenever `requestDiagnostics` is served.

## Determinism preservation

- M3.2 golden LM descent scenario: unchanged; verified by the existing
  `MissionRuntime.test.ts` golden checkpoints (LM physics is a pure
  kernel and does not depend on which AGC WASM the Worker loaded).
- M2 event-log determinism: the extended runtime is bit-identical to the
  frozen runtime across the six P3 parity scenarios (see
  `docs/M3_3A2_P3.md`); the packet stream and erasable snapshot the
  Worker observes are byte-for-byte identical to the pre-promotion
  behaviour.

## Test coverage added or updated

- `src/agc/__tests__/canonicalRuntime.test.ts` — descriptor is coherent
  with the two on-disk artifacts, production URL helpers resolve to the
  extended artifact, and the loaded WASM reports the identity fields the
  descriptor advertises. Dormancy at boot is asserted here too.
- Existing suites unchanged and green: `hwioParity`, `hwioDormancy`,
  `hwioExtWasm`, `AgcCoreAdapter`, `MissionRuntime`, `determinism`,
  `checksum`, event-log canonical/import/build, lessons 1–6.

## Provenance display

- `src/routes/sources.tsx` — Emulator section now names the extended
  runtime and points to `UPSTREAM.md` for full byte-parity provenance.
- `src/third-party/webagc/UPSTREAM.md` — already carries the extended
  artifact SHA-256 and describes it as the M3.3A2-P3 build.

## What did NOT change

- Legacy ABI (nine exports) is unaltered on both artifacts.
- No production code enables trace collection.
- No route or component ships a second AGC core: `AgcSession` still owns
  the single `AgcWorkerClient` for the whole app lifetime.
- LM physics kernel and MissionRuntime tick phase order are unchanged.
